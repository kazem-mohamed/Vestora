# دليل ملفاتك العملي — قاعدة البيانات

الملف ده مش للمذاكرة النظرية — ده اللي بتفتحه وإنت قاعد على الجهاز.
بيقولك ملفاتك فين بالظبط، ومحتاج تنزّل إيه، وتكتب إيه في الترمينال.

الملف النظري الكامل: `study.pdf` في نفس الفولدر.

---

## ١. الأدوات اللي محتاجها

| الأداة | لإيه | إزاي تتأكد إنها موجودة |
|---|---|---|
| .NET 8 SDK | تبني وتشغّل الـ API وتستخدم أوامر EF | `dotnet --version` |
| `dotnet-ef` | أوامر الترحيلات | مثبّتة **محليًا** في المشروع — شوف تحت |
| محرّر كود | تقرا وتعدّل | VS Code أو Visual Studio |
| متصفّح قواعد بيانات | تبصّ على الجداول والبيانات فعلًا | SSMS أو إضافة SQL Server في VS Code |

### ملاحظة مهمة عن `dotnet-ef`

الأداة **مش مثبّتة على مستوى الجهاز** — دي أداة محلّية معرّفة في
`MyAppApi/MyAppApi/.config/dotnet-tools.json`.

يعني أول مرة تشتغل على الجهاز لازم تعمل:

```bash
cd MyAppApi/MyAppApi
dotnet tool restore
```

لو مقتش كده، أي أمر `dotnet ef` هيقولك إن الأمر مش موجود.

## ٣. الأوامر

كل الأوامر دي بتتنفّذ من `MyAppApi/MyAppApi` إلا لو مكتوب غير كده.

### أول مرة على الجهاز

```bash
cd MyAppApi/MyAppApi
dotnet tool restore
dotnet build
```

### تشوف الترحيلات الموجودة

```bash
dotnet ef migrations list
```

### تشوف شكل الـ SQL من غير ما تطبّق أي حاجة

```bash
dotnet ef migrations script
```

ده أأمن أمر عندك — بيطبع الـ SQL على الشاشة ومبيلمسش القاعدة.

### تولّد ترحيل جديد

```bash
dotnet ef migrations add اسم_وصفي_للتغيير
```

بعد الأمر ده **افتح الملف اللي اتولّد واقراه** قبل أي حاجة تانية.

### تلغي ترحيل ولّدته بالغلط (طالما لسه ماتطبّقش)

```bash
dotnet ef migrations remove
```

### تطبّق على قاعدة البيانات

```bash
dotnet ef database update
```

> ⚠️ **قف هنا.** الأمر ده بيغيّر قاعدة بيانات **مشتركة** الفريق كله شغّال عليها.
> مفيش نسخة محلّية ومفيش تجربة. اقرا `Up()` و `Down()`، اتأكد إن التغيير إضافي
> (عمود nullable أو جدول جديد)، وقول للفريق **قبل** ما تشغّله مش بعده.

### ترجع لترحيل قديم

```bash
dotnet ef database update اسم_الترحيل_اللي_قبله
```

## ٤. إزاي تتتبّع «كلاس ← جدول» عمليًا

عايز تعرف عمود معيّن طلع منين؟ امشي الطريق ده:

1. افتح الكلاس في `Data/Models/` — شوف الـ property واسمها ونوعها.
2. افتح `Data/AppDbContext.cs` ودوّر على اسم الكلاس في `OnModelCreating` —
   هنا هتلاقي أي إعداد صريح (دقّة، فهرس، علاقة، فلتر).
3. لو مالقتش إعداد صريح، يبقى العمود ماشي بالاتفاقيات الافتراضية.
4. عايز تشوف الـ SQL الفعلي؟ `dotnet ef migrations script` ودوّر على اسم العمود.

## ٥. تشغيل الـ API نفسه

```bash
cd MyAppApi/MyAppApi
dotnet run
```

لو التطبيق رفض يشتغل وقال حاجة عن مفتاح Stripe — ده **مقصود**. التطبيق بيرفض
يشتغل بمفتاح إنتاج، ولازم يكون مفتاح تجريبي (`sk_test_`).

## ٦. الاختبارات

فيه ٤٨ اختبار وحدة (مش على قاعدة البيانات — على منطق الحسابات والمراحل):

```bash
cd MyAppApi
dotnet test MyAppApi.Tests/MyAppApi.Tests.csproj
```

بيخلّصوا في أقل من ثانية لأنهم مش بيفتحوا قاعدة بيانات أصلًا. **مفيش عندنا
اختبارات integration على قاعدة البيانات** — دي فجوة معروفة وموثّقة في
`docs/09-STATUS.md`، ولو اتسألت عنها قول كده بصراحة.
